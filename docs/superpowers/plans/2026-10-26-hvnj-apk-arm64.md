# HVNJ APK ARM64 Implementation Plan

> For agentic workers: use executing-plans for inline integration; dispatch independent packaging and feature engines with dispatching-parallel-agents. No commits without a new request.

Goal: build a separately signed ARM64 APK with the9 PC mod features and native game menu, preserving original APK.
Architecture: libhvnjmod.so bootstrap waits for libil2cpp, resolves validated Unity6 method/field interfaces, hooks main update/menu/target selection; independent feature engines call a shared runtime adapter. Repackage original APK with a startup loader, ARM64 library and fresh signature.
Tech stack: Android NDK C/C++, Dobby hook dependency, Cpp2IL metadata39 mapping, Python build/tests, smali/Android signing tools.
Spec: docs/superpowers/specs/2026-10-26-hvnj-apk-arm64-design.md (approved M3).

Global constraints: work only inside requested HVNJ_MOD_APK artifact folder for implementation; keep PC source and APK input untouched; ARM64 first; package com.g4m.hocvienninja; no0.3s feature;9 default-off flags; no unsupported packet fields or spending xu in automation. Preserve analysis provenance. No commit/push. Spec/plan are the only new documents outside the artifact folder.

## Interfaces

`src/hv_runtime.h` owns runtime API; `hv_call(obj,class,method,argc,args)` uses boxed object return, value args by address and reference args directly. Runtime field helpers support objNULL for static fields and resolve inherited fields. Shared HvConfig has9 flags in order mob/die/trial/stage/quest/tathu/party/sell/stone, stone_lo/hi and accept_option. Main update calls hv_features_tick and hv_bag_tick. Selection hooks call hv_features_target(original,task). Bag exposes busy/preview APIs. Profile generator reads only this APK's Cpp2IL output; no PC class offsets.

## Review focus

- Runtime readiness/GC/thread attachment and Unity6 layouts: no Unity2020 class-struct offsets.
- ARM64 relocated hooks and16KB ELF alignment; fail safely on profile mismatch.
- Feature flags off preserve original behavior; reset transitions do not run transactions.
- Bag sell/refine/store serialized with server acknowledgement; unknown item data is kept.
- Signed APK structurally valid does not prove login/server gameplay works; report test limits.
